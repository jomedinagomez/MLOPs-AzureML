# Customer H2O Binary-Model Intake

Place the customer model and representative test files in this directory during the workshop. Git ignores those files.

## Required Inputs

1. An H2O binary model created with `h2o.save_model()`.
2. The exact H2O version used to save the model.
3. Feature names in their required order.
4. The list of categorical features.
5. `golden_input.csv` containing representative feature rows.
6. `golden_expected.csv` containing one `predict` column generated in the source environment.

The packaging notebook creates `model_manifest.json`, calculates SHA-256 values, loads the model with the exact H2O version, and verifies golden prediction parity before Azure registration is allowed.

## Example Layout

```text
customer_bundle/
  README.md
  model
  golden_input.csv
  golden_expected.csv
  model_manifest.json       generated by the workshop
```

Do not use `latest` for the model or environment version. H2O binary models must be loaded with the same H2O version used to save them.
